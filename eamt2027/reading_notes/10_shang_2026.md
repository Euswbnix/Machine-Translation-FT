- [x] **spBLEU 使用哪个 tokenizer?COMET 使用哪个模型?**

  两项均有明确报告。

  | Metric | Implementation |
  |---|---|
  | spBLEU | SacreBLEU |
  | BLEU tokenizer | `flores200` |
  | COMET | `Unbabel/wmt22-comet-da` |
  | COMET type | Reference-based |
  | SacreBLEU version | Not reported |
  | Full SacreBLEU signature | Not reported |
  | COMET package version | Not reported |
  | Exact COMET checkpoint revision | Not reported |

  - Section 3.3 的 Footnote 4 明确指定 SacreBLEU 的 `flores200` tokenizer。Footnote 5 明确指定 `Unbabel/wmt22-comet-da`。
  - Table 5 的 COMET 不是 COMET-KIWI,也不是 XCOMET。COMET 使用 source、hypothesis 和 reference 三项输入。
  - COMET 在论文中按照 0–100 的尺度报告,即 83.8 对应原始模型输出尺度上的 0.838。

  spBLEU 复现代码:

  ```python
  from sacrebleu.metrics import BLEU

  bleu = BLEU(tokenize="flores200")
  score = bleu.corpus_score(hypotheses, [references])

  print(score.score)
  print(bleu.get_signature())
  ```

  COMET 复现代码:

  ```python
  from comet import download_model, load_from_checkpoint

  checkpoint = download_model("Unbabel/wmt22-comet-da")
  model = load_from_checkpoint(checkpoint)

  data = [
      {"src": src, "mt": hyp, "ref": ref}
      for src, hyp, ref in zip(
          sources, hypotheses, references
      )
  ]

  result = model.predict(data, batch_size=32, gpus=1)

  print(result.system_score)
  print(result.system_score * 100)
  ```

  本文使用的三个 COMET 系列模型:FLORES+ 评测用 `Unbabel/wmt22-comet-da`;WMT24++ 的 XCOMET 评测用 `Unbabel/XCOMET-XXL`;WMT24++ 的 COMETKiwi 评测用 `Unbabel/wmt23-cometkiwi-da-xxl`。后两个不是 Table 5 所使用的评价指标。

  正式记录:**spBLEU was computed using SacreBLEU with the flores200 tokenizer, and COMET was computed using the reference-based Unbabel/wmt22-comet-da checkpoint.**

  来源:Section 3.3,Footnotes 4–7。

- [x] **8-shot 的示例如何选择?**

  Section 4.2 和 Footnote 8 明确报告:

  - 从 FLORES+ development dataset 中随机抽取八个平行句对。
  - 对于同一个翻译方向,在整个评估过程中复用相同的八个示例。不是为每个测试句子重新随机抽取,也不是按语义相似度检索。
  - 使用 OpenICL 框架完成 in-context learning 实验。
  - Prompt 模板采用 `<X>=<Y>`,其中 X 是源语言句子,Y 是对应目标语言句子。

  原文没有报告:抽样随机种子;八个示例的具体句子或 example IDs;是否无放回抽样;示例的排列顺序;示例之间的具体分隔符;不同模型是否严格共享相同的 demonstration IDs;不同翻译方向是否共享同一组跨语言平行句 IDs;Section 4.2 基线实验的完整 decoding configuration;最大生成长度、停止条件及输出后处理。

  Section 5.3 明确报告 greedy decoding,但该说明属于后续 model/data scaling 实验,不能直接认定 Section 4.2 的所有原始 LLM 基线使用完全相同的解码配置。

  E1.0 可以采用以下近似复现模板:

  ```text
  {english_example_1}={french_example_1}
  {english_example_2}={french_example_2}
  {english_example_3}={french_example_3}
  {english_example_4}={french_example_4}
  {english_example_5}={french_example_5}
  {english_example_6}={french_example_6}
  {english_example_7}={french_example_7}
  {english_example_8}={french_example_8}
  {english_test_sentence}=
  ```

  上述换行方式是建议的复现实现,并非已经核实的原始 OpenICL 完整模板。

  正式记录:**Eight randomly selected parallel sentence pairs from the FLORES+ development set were reused as fixed in-context exemplars for each translation direction. The prompt followed the X=Y format and was implemented using OpenICL. The sampling seed, exemplar IDs, exact formatting, and complete decoding configuration were not reported.**

  来源:Section 4.2,Footnotes 8–9。

**建议的 E1.0 通过标准:** spBLEU ≥ 37.7(参考 39.7);COMET ≥ 0.818(参考 0.838)。

- 上述允许偏差为 2 spBLEU points 和 0.020 COMET,是我们自行设定的初步工程验收容差,并非原文提供的统计置信区间。
- 如果单个 seed 低于门槛,应先检查 demonstration seed、prompt 格式、输出截断、重复生成和数据版本,而不是立即判断模型存在问题。
- 建议至少运行三个 demonstration seeds,报告 mean ± standard deviation。
- 如果三个 seed 均显著低于原文结果,应检查 Base/Post-trained checkpoint 差异。必要时使用 `Qwen/Qwen3-1.7B` 作为诊断性对照,但不应在没有说明的情况下更换 E1.0 主实验模型。
- 后续 LoRA 实验应始终使用同一模型初始化、测试集版本、demonstration IDs、prompt、decoding configuration 和评价指标。
- 如果微调后采用 zero-shot evaluation,则应另外建立微调前的 zero-shot baseline,不能直接将 8-shot 的 39.7 / 83.8 当作微调前后遗忘分析的基准。

**最终核对结论**

- 39.7 spBLEU / 83.8 COMET:确认无误。
- Qwen3-1.7B-Base:合理推断,但原文没有明确确认 checkpoint。
- FLORES+ devtest:高度可信,具体 release version 未报告。
- spBLEU tokenizer:明确为 flores200。COMET checkpoint:明确为 `Unbabel/wmt22-comet-da`。
- 8-shot:从 dev 随机抽取八个平行句对,同一方向固定复用。
- Demonstration seed、IDs、完整 prompt 格式及解码配置:未报告。
- 因此,这两个分数适合作为 E1.0 的外部 sanity-check reference,而不是严格的逐点复现门槛。

**Experimental Setup 英文表述(草稿)**

Following Shang et al. (2026), we evaluate the pretrained Qwen3-1.7B-Base model on the English-to-French FLORES+ devtest split using eight fixed in-context exemplars randomly sampled from the development split. Translation performance is measured using SacreBLEU with the flores200 tokenizer and the reference-based wmt22-comet-da checkpoint. Shang et al. reported 39.7 spBLEU and 83.8 COMET for Qwen3-1.7B under an 8-shot setting. As their exact model checkpoint, dataset revision, demonstration identities, and sampling seed were not specified, we use these scores as approximate external sanity-check references rather than strict reproduction targets.

## Claude 的补充(2026-11-27)

1. **预注册草稿里试跑门槛 P1 的三个"待核对"现在有答案了,我已经把草稿更新。** 测试集是 FLORES+ devtest(1,012 句),示例取自 dev;spBLEU 用 sacreBLEU 的 flores200 分词;COMET 是 wmt22-comet-da。仍然不明的只有一项:Table 5 的 Qwen3-1.7B 是 Base 还是后训练版。
2. **门槛容差:草稿建议 ±1.5 spBLEU / ±1.0 COMET,你建议只设下限(−2.0 / −2.0)。我建议取你的宽度,但保持双向。** 放宽有道理:示例的编号、种子和提示格式他们都没给,示例不同分数就会不同。保持双向的理由:如果我们的分数明显高于 39.7(比如 44),同样说明设置对不上(最可能是他们用的不是 Base,或者数据版本不同),只设下限就发现不了。具体建议:三组示例(种子 42、123、2026)的平均分落在 39.7 ± 2.0 spBLEU 且 83.8 ± 2.0 COMET 之内算通过;之后固定用种子 42 那一组,并把 8 个示例的编号写进预注册。这是第 2 项待定决定,由你定。
3. **门槛不过时先做诊断,这个分支要事先登记。** 草稿第 3 项现在写的是"门槛不过就换 Gemma-3-4b-pt 作主模型"。但你查到参照分数本身有歧义(Base 还是后训练版),门槛不过可能是参照的问题,不是我们的问题。建议在第 3 项里加一个事先写好的分支:门槛不过时,先用同样的提示和示例评一次 `Qwen/Qwen3-1.7B`(后训练版);如果它落在容差内,就记录"Shang 的数字对应后训练版",主模型仍用 Base,并以我们自己测到的 Base 8-shot 分数作为参照;两个都不过,才按原来的退路换模型。分支写在跑之前,就不算事后改门槛。
4. **两种提示格式要分清。** 复现 Shang 的门槛用他们的 `X=Y` 格式;草稿里微调用的提示是 `Translate this from English to French:\nEnglish: {src}\nFrench:`,微调后的模型按这个提示零样本解码。两者不是一回事,预注册里要各写各的。
